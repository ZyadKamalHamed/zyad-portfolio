Develop 01

SafeSize Triage

Project
SafeSize × The General Store
Role
Discovery · Data model · UX · Security

SafeSize 3D foot scanners sit on shop floors across Asia-Pacific. When one breaks, the fix used to start with a phone call. SafeSize Triage replaces that: machines report their own faults, store staff report through an AI chatbot, and every fault becomes a ticket routed to the right support tier across three countries.

Scoped and designed end to end, from discovery and data model to ticket lifecycle and 21 prototype screens, with a deployed Postgres schema where row-level security, not application code, decides who sees what. Every region choice keeps the data in Australia.

Next.js · Supabase Postgres · Claude on AWS Bedrock · Twilio

Develop 02

CourtIQ

Context
UTS Tech Fest 2026 AI Showcase
Role
Court vision mapping, in a team of three

Basketball footage in, a top-down court out. CourtIQ detects players, tracks shots, and projects every player onto a 2D court plan, frame by frame. Built with two others and presented at the UTS Tech Fest 2026 AI Showcase.

I owned court vision mapping. I fine-tuned a YOLO26n-pose network on AWS SageMaker to find 33 court keypoints in every frame across an 851-image dataset, reaching 0.994 keypoint mAP50 and 0.853 mAP50-95. A per-frame homography turns those keypoints into the projection that the rest of the pipeline plots on.

Decision We treated the court as a pose problem rather than a segmentation one. Keypoints hand you a homography directly, so the projection survives camera pans and partial occlusion instead of collapsing whenever a player stands on a line.

Python · YOLO26n-pose · OpenCV · AWS SageMaker · Next.js

Develop 03

JARVIS

Project
Personal AI operating system
Role
Everything

A personal AI operating system that runs as one zero-dependency Node process over a folder of JSON, with a browser as the only client. Scheduled agents write the morning briefing, plan the day, and file the tasks. The dashboard renders that state and reads it back.

It rewrites itself nightly, one small change at a time, and every change is gated on its own test run before it is kept.

Decision Stealth mode strips personal data server-side, before the response is serialised, rather than hiding it with CSS on the client. Anything the browser never receives cannot leak off a shared screen.

Node · JSON store · Web Speech · Tailscale

Develop 04

UTS FEIT RAG Chatbot

Context
UTS group project
Role
Retrieval pipeline and evaluation

A retrieval-augmented generation chatbot that answers UTS student questions about enrolment, assessment, key dates, and campus life. It retrieves from indexed UTS policy documents and handbooks, and searches the web when the answer is not already in the corpus.

I evaluated it on retrieval accuracy and answer usability against real student scenarios rather than generic benchmarks. A wrong answer about a census date costs a student money, so usability was the metric that mattered.

Decision Search results are filtered to trusted UTS domains before anything is scraped, and the whole stack runs locally through Ollama. The model cannot answer a policy question from a random forum post, and no student query leaves the machine. The cost is a smaller model and slower answers.

Python · LangChain · Ollama · Chroma · FastAPI · Streamlit

question ↓ UTS domain filter ↓ scrape + indexed PDFs ↓ llama3 8b, local ↓ answer

Two retrieval paths, indexed documents and filtered web search, converge on one answer. The model only ever sees text that came from a UTS source.
